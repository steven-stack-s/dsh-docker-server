## 一、版本线现状与判定

### 1.1 dist-tag 实测（2026-11-09）

| tag | 指向 | 说明 |
|---|---|---|
| `latest` | **`0.2.2-rc.1`** | 稳定推荐版 |
| `next` | **`0.2.2-rc.1`** | 与 latest 同一版本 |
| `alpha` | `0.2.2-alpha.3` | 比 rc.1 更早发布 |

### 1.2 ⚠ 本项目历史上的第一次：锁定的版本就是 `latest`

以往各轮，本项目锁定的版本要么挂在 `alpha`、要么挂在 `next`，`latest` 总是指向更旧的版本
（如上一轮 latest 还是 `0.2.1-rc.2`）。**本轮是第一次，锁定的 `0.2.2-rc.1` 同时是 `latest`
和 `next`。**

这意味着：用户装本项目镜像拿到的**不是预览版，而是上游自己标注的稳定推荐版**。这是本项目
跟随策略的一个里程碑 —— 从"被迫追预览线拿新能力"走到了"与上游稳定推荐版对齐"。

但**结论不变**：仍必须写全版本号（`@0.2.2-rc.1`），因为 `latest` 是会漂移的别名，
上游下次前进后它就指向别处了；Dockerfile 里钉死显式版本的理由（避免同一份 Dockerfile
在不同时间构建出不同版本）依然成立。

### 1.3 0.2.2 线完整版本序列

```
0.2.2-alpha.2  →  0.2.2-alpha.3  →  0.2.2-rc.1
```

发布时间（UTC）：

| 版本 | 发布时间 |
|---|---|
| `0.2.2-alpha.2` | 2026-10-27T19:10 |
| `0.2.2-alpha.3` | 2026-11-03T07:48 |
| `0.2.2-rc.1` | **2026-11-04T09:20** |

### 1.4 判定：跟 `0.2.2-rc.1`

- **方向是前进**：`0.2.2-rc.1` > `0.2.2-alpha.3`（同数字段下 rc 高于 alpha），
  且发布时间晚于 alpha.3。
- **跨过了 alpha.3**：本项目上一轮锁的是 `alpha.2`，本轮直接到 `rc.1`，**跳过了中间版本**。
  所以本次**不是**"alpha.2 → rc.1 的小步" —— alpha.3 里的上游改动也一并包含进来了。
  这是核对时要注意的：只看 `alpha.2 → rc.1` 的差异，会漏掉"这中间还有 alpha.3"这个事实。
- **稳定性回正**：上一轮因 0.2.2 无 rc 而被迫走 alpha，本轮兑现了"rc 出来就回 rc 线"。

### 4.3 `applyPatch: false` 是什么

上游新引入的配置项，挂在既有 `tool-fs` 条目上，共 **4 处**（顶层 1 处 + 3 处嵌套）：

```

663:      - id: tool-fs          ← 嵌套（第 1 处）
828:      - id: tool-fs          ← 嵌套（第 2 处）
1094:     - id: tool-fs          ← 嵌套（第 3 处）
```

它是 `dsh-fs-patch`（本轮新增但**未被装载**的包）的能力开关，**默认 `false`（关闭）**。
由于这些 `tool-fs` 条目本来就处于 `disabled: true`，且开关默认关闭，**对本项目行为无影响**。

## 七、差异规模

| 口径 | `alpha.4→rc.2` | `rc.2→alpha.2` | **`alpha.2→rc.1`** |
|---|---|---|---|
| 全树 diff（排除 `*.map`/`*.d.ts`） | 11,114 | 100,461 | **72,726** |
| 版本号变化的包数 | 300 | 301 | **324**（共同包 328 个中） |
| 渲染配置 diff | 6 行 | 45 行 | **13 行** |
| 包级变化 | +2 / −0 | +26 / −1 | **+3 / −3** |
| 渲染条目变化 | +2 / −0 | +7 / −6 | **+2 / −0** |

> **测量方法备注（沿用前两轮的教训）**：全树 diff 在受限环境下耗时数分钟，极易被 `timeout`
> 截断而给出偏小的假值（曾出现 5,136 / 8,047 两个截断值，真实值是 11,114）。
> **本轮仅在带完成标记（`DIFF-DONE`）时才采信数值**，绝不用中途读数 —— 本轮已取得完成标记，
> 读得 **72,726 行**，故采信该值。
>
> ⚠ **三个数字（11,114 / 100,461 / 72,726）差异巨大，需要正确解读**，它们与"风险大小"无关：
> - `rc.2→alpha.2` 的 100,461 含 **包级 +26**，`diff -r` 会把新增包的整份文件逐行计入；
> - 本轮 `alpha.2→rc.1` 的 72,726 虽然包总数不变（+3/−3），但 **324 个共同包版本号全部变动**
>   （上游整体发版），构建产物几乎全部重写；
> - 因此 **diff 行数不等于受影响面**。判定影响仍以「实际装载的条目数 + 渲染差异 +
>   逐契约核对」为准 —— 本轮渲染差异只有 13 行且零移除，这才是真正的信号。
