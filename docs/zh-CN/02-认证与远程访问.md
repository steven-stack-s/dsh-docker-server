# 02 · 认证与远程访问

> [English](../en/02-authentication-remote-access.md) | [简体中文](02-认证与远程访问.md)

**自 v0.6.0 起，认证插件默认就已装好**：镜像内置 [dsh-remote](https://github.com/xgone/dsh-remote)，
首启自动创建一个管理员账号（用户名 `admin`，密码为随机 16 位），密码**只打印一次**在首次启动日志里：

```bash
docker logs dsh 2>&1 | grep -A9 'first-boot admin credentials'
```

拿到密码后访问 `http://<主机IP>:3080` 登录，并尽快在「设置 → 登录与账号」改密 + 开启 MFA。
想要关掉认证层（回到无认证的内网直连模式）见下方 §3。

## 访问方式总览

| 方式 | 安全性 | 适用场景 |
|---|---|---|
| 本机访问（`127.0.0.1:3080`） | 最高 | 部署在同一台机器的浏览器 |
| 内网直连 + 账号登录（**默认**） | 高（账号密码，可选 MFA） | 局域网内使用 |
| SSH 隧道 | 高（加密） | 单人在外临时访问 |
| 反向代理 + HTTPS | 高（认证层 + HTTPS） | 长期远程访问 |

> 浏览器限制：`dsh web` 的部分功能（如 `crypto.randomUUID`、settings）要求**安全上下文**
> （HTTPS 或 localhost）。内网通过 IP 直连时若遇到相关报错，属浏览器安全策略，
> 可用 `localhost` 访问、SSH 隧道或反向代理 HTTPS 解决。

## 1. 默认认证（开箱即用）

镜像内置认证插件并在首启装好，**无需任何手工步骤**。相关行为：

- **账号数据**存于 `$DSH_HOME/auth/store.json`（挂载卷内，容器重建不丢），密码以 scrypt 哈希存储。
- **密码只打印一次**：只在真正创建账号的那一次启动打印。之后重启/重建容器都不会再显示
  —— 避免密码被写进每一次 `docker logs`（日志常被转发、归档、贴进 issue）。
- **忘记密码**：删除 `<DSH_DATA_DIR>/auth/store.json` 后重启容器，会重新生成随机密码并打印。
  ⚠ 这会一并清掉所有账号与 MFA 配置。
- **想自己定密码**：在 `.env` 里设 `DSH_ADMIN_PASSWORD=你的密码`（≥6 位）。设了就不打日志。
  仅当账号库为空时生效 —— 已有账号时不会被覆盖。
- **想改用户名**：`.env` 里设 `DSH_DEFAULT_ADMIN_USER=你的用户名`（同样只在账号库为空时生效）。

> 原理：entrypoint 在首启把 `bootstrap: {username, password}` 写进
> `$DSH_HOME/profiles/web/cordis.patch.yml`（属主 0600），插件在账号库为空时据此预置首个
> 管理员（role 恒为 `admin`，且是不可删除的 root 账号）。

## 2. 登录并开启 MFA

- 访问 `http://<主机>:3080`，用 `admin` + 首启日志里的密码登录
- 设置 → 登录与账号 → 双重验证（MFA）→ 用 Google Authenticator / 1Password 扫码
- **MFA 必开**：若通过反向代理暴露到公网，认证层是唯一防线

> 首次登录后建议改密（设置 → 登录与账号）。改密后 `cordis.patch.yml` 里的明文 `bootstrap`
> 段即失效（账号已存在时它不再被读取）；如需彻底清除明文，删除该文件里的
> `bootstrap:` 两行即可（保留 `enabled: true`）。

## 3. 关闭认证（回到内网直连）

认证是**默认开启**的。若你的部署只在完全可信的内网（或本机），可以关掉：

```bash
# .env
DSH_SETUP_REMOTE=off
```

```bash
docker compose up -d
```

关闭后：不装插件、不建账号，回到历史行为 —— **完全没有认证层**。此时若用局域网 IP 或域名
访问，必须自行配置 `DSH_TRUSTED_HOSTS`，否则页面能打开但 `/api` 会 403（见 §4）。

> ⚠ 把 `3080` 暴露到公网**又**关掉认证，等于任何人打开页面就得到一个拥有完整 agent 权限的
> 会话（能执行命令、读写工作区）。除非你另有外层认证（VPN / 反代的 auth），否则不要这么做。

## 4. 手工安装 / 升级插件

镜像已内置，一般无需手工安装。需要**换版本或重装**时：

```bash
# 升级到指定版本（插件与账号数据写入 /data/dsh 卷，容器重建不丢）
docker exec dsh dsh plugin --profile web add @xgone/dsh-remote@<版本>
docker restart dsh
```

> 💡 entrypoint 只在 profile 里**没有**该插件时从镜像 seed 复制。你手工升过的版本会被保留，
> 不会被镜像顶回旧版 —— 与 dsh 本体的"seed 只升不降"约定不同（插件升级一律走 `dsh plugin`）。
> 注意 `dsh plugin add` 需要联网（它转发给 pnpm）。

### 配置式 bootstrap（无浏览器场景）

若要在**不打印日志**的前提下预置凭据（例如由部署脚本统一注入密码），除 `DSH_ADMIN_PASSWORD`
外，也可直接编辑 `profiles/web/cordis.patch.yml`（挂载在 `/data/dsh` 卷内）里 entrypoint 写入的
托管块：

```yaml
- id: remote
  config:
    enabled: true
    bootstrap:             # 仅当账号库为空时使用
      username: admin
      password: '一个强密码'
```

> entrypoint 用 `# >>> dsh-docker-server: default auth plugin (managed block ...) >>>` 标记
> 自己写的那一段；**托管块会在每次启动被重写**。要长期自定义，请删掉标记行或改用账号库
> （`enabled` 之外的字段自定义同理）。

## SSH 隧道（单人在外临时访问）

```bash
# 本地端口转发：把远程 3080 映射到本机 3080
ssh -L 3080:127.0.0.1:3080 你的账号@主机IP
# 然后浏览器打开 http://127.0.0.1:3080
```

适合 Windows/Mac/Linux 自带 ssh 的场景，无需额外配置。

## 反向代理 + HTTPS（长期远程访问，推荐）

> ℹ 装了认证插件（默认）时不需要配 `DSH_TRUSTED_HOSTS`：插件的 `trustProxy` 会在请求通过
> 登录认证后，把 Host/Origin 归一为 loopback 再交给 dsh 核心，因此任何域名/隧道 Host 登录后
> 都能正常使用 `/api`（2026-09-17 实测验证）。访问控制由账号密码 + MFA 承担。
>
> 只有**关掉了认证插件**（`DSH_SETUP_REMOTE=off`）而又需要用域名/局域网 IP 直连时，才必须加白：
> 在 `.env` 写 `DSH_TRUSTED_HOSTS=app.example.com`（多个用逗号分隔，可带端口）——否则页面能打开、
> 但 `/api` 会被 403 拒绝（表现为"界面空白 / 连接异常"）。

以 Caddy（自动 HTTPS）为例，Nginx 同理：

```bash
# Caddyfile（域名需解析到主机；80/443 端口开放）
你的域名.com {
    reverse_proxy 127.0.0.1:3080
}
```

```bash
# 以 Docker 运行 Caddy
docker run -d --name caddy \
  -p 80:80 -p 443:443 \
  -v /path/to/Caddyfile:/etc/caddy/Caddyfile \
  -v caddy_data:/data \
  caddy:2
```

> 反代前务必确认认证插件已启用（默认即是）并开启 MFA（见第 2 节）。

## 安全清单

- [ ] 远程访问时：强密码 + **MFA（TOTP）**
- [ ] 不要把 `3080` 直接映射到公网
- [ ] 不要在有公网入口的部署上设 `DSH_SETUP_REMOTE=off`
- [ ] 第三方插件有完整权限，安装前查看源码
- [ ] 定期备份（见 [03](03-升级与维护.md)）
