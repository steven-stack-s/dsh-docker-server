# 05 · 平台差异

> [English](../en/05-platform-differences.md) | [简体中文](05-平台差异.md)

本方案以**通用 Linux + Docker 引擎**为基准编写。各平台本质相同（都是 Linux 容器），差异仅在路径、容器管理器和网络设置。按你的平台查看对应章节。

## 1. 通用 Linux 服务器（推荐基准）

- 云主机 / VPS / 家用迷你主机 / 软路由等，系统为 Ubuntu/Debian/CentOS/OpenWrt 等
- 安装 Docker Engine + compose 插件后，按 [01](01-快速开始.md) 操作即可
- 国内网络建议先配置 registry 镜像加速：

```bash
# /etc/docker/daemon.json
{
  "registry-mirrors": ["https://docker.m.daocloud.io", "https://dockerproxy.com"]
}
systemctl restart docker
```

## 2. 群晖 DSM

> ⚠ **用 NAS 的 IP 访问时**（`http://192.168.x.x:3080`）：认证插件**默认已装**，登录后即可用
> （Host 会被归一为 loopback），**不需要**配 `DSH_TRUSTED_HOSTS`。只有当你设了
> `DSH_SETUP_REMOTE=off` 关掉认证时，才必须把 `192.168.x.x:3080` 写进 `.env` 的
> `DSH_TRUSTED_HOSTS`：dsh 只信任 loopback 或白名单 Host，未加白会表现为"页面能开、`/api` 403"。
> 详见 [02](02-认证与远程访问.md)。

- **安装**：套件中心 → 搜索安装「Container Manager」（Docker 官方套件），含 compose 支持
- **路径**：共享文件夹挂载在 `/volume1/...`，建议在共享文件夹下建部署目录（如 `/volume1/docker/dsh-docker-server/`），卷路径用绝对路径写入 `.env`：

  ```
  PROGRAMS_DIR=/volume1/docker/dsh-docker-server/programs
  DSH_DATA_DIR=/volume1/docker/dsh-docker-server/dsh
  WORKSPACE_DIR=/volume1/docker/dsh-docker-server/workspace
  ```

- **命令**：通过 SSH 登录群晖执行 `docker compose ...`；也可在 Container Manager 图形界面的「项目」中导入 `docker-compose.yml`
- **注意**：`compose.yaml` 语法兼容；Container Manager 项目不支持所有变量插值，建议保持 `.env` 与 compose 同目录

## 3. 绿联 UGOS Pro

- **安装**：应用中心安装「Docker」，SSH 需在控制面板 → 终端开启
- **路径**：共享文件夹在 `/volume1/...`，方法同群晖
- **命令**：SSH 登录后 `docker compose up -d`
- **容器管理**：也可在 UGOS Docker 图形界面导入 compose 文件

## 4. 威联通 QTS / QuTS hero

- **安装**：App Center 安装「Container Station」，SSH 开启（控制台 → 网络与文件服务 → Telnet/SSH）
- **路径**：共享文件夹在 `/share/...`，如 `/share/Container/dsh-docker-server/`
- **命令**：SSH 登录后 `docker compose up -d`

## 5. Windows / macOS Docker Desktop

- **安装**：官网下载 Docker Desktop（Windows 需 WSL 2 或 Hyper-V 后端；macOS 需 Apple Silicon 或 Intel）
- **命令**：在 PowerShell / Terminal 中执行 `docker compose ...`
- **路径**：`.env` 中使用绝对路径，Windows 示例：

  ```
  PROGRAMS_DIR=D:/docker/dsh-docker-server/programs
  DSH_DATA_DIR=D:/docker/dsh-docker-server/dsh
  WORKSPACE_DIR=D:/docker/dsh-docker-server/workspace
  ```

- **端口**：Docker Desktop 自动处理端口映射，`http://localhost:3080` 访问
- **macOS 资源**：Docker Desktop → Settings → Resources 调整内存/CPU（本方案默认 2g/2 核）
- **Windows 文件挂载性能**：大量小文件 IO 建议把数据目录放在 WSL 2 内部文件系统（`\\wsl$\docker-desktop\...`）以获得更好性能
- **注意**：PowerShell 中 `$` 在 compose 变量里有特殊含义时用反引号转义，或直接写 `.env` 值

## 6. 无 Docker 的轻量环境（K3s / Podman 等）

- Podman：`podman-compose up -d` 或 `podman play kube`（compose 转 k8s 需转换工具）
- 本仓库文件基于 Docker compose v2 语法，K3s 等编排需自行转换；推荐直接用 Docker
