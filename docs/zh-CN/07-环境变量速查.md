# 07 · 环境变量速查

> [English](../en/07-environment-variables.md) | [简体中文](07-环境变量速查.md)

本文档是 `.env.example` 之外、写在 `docker-compose.yml` 的 `${VAR:-default}` 兜底里的**高级调优变量**完整速查。

`.env.example` 只列了日常部署用得到的 12 项（见文件顶部注释），其余约 25 个变量对绝大多数用户不需要动；想自定义时，按下表说明**二选一**覆盖默认值：

- **方式 A · 改 compose 默认值**：直接编辑 `docker-compose.yml` 的 `${VAR:-default}` 部分，例如把 `mem_limit: ${MEM_LIMIT:-2g}` 改成 `mem_limit: ${MEM_LIMIT:-3g}`。
- **方式 B · 在 `.env` 追加同名变量**：`docker compose` 会让 `.env` 里出现的变量覆盖 compose 中的默认值，等价于"显式传 env"。注意 `.env` 里的值**不会**进入容器 `environment:` 块（除非 compose 里显式列出），所以这种方式只对 compose 里有 `${VAR:-...}` 的变量生效。

## 1. 自愈 / 救生舱（RESCUE_*）

| 变量 | 默认 | 含义 |
|---|---|---|
| `RESCUE_START_TIMEOUT` | `120` | 救生舱内等待 dsh 就绪的探测超时（秒）。**必须 < compose healthcheck 的 `start_period`（默认 300s）**，否则 rescue 会先于 docker 放弃而误回滚仍在冷启动的 dsh。 |
| `RESCUE_KEEP` | `3` | 保留的最近可用快照数；最新一份健康基线被钉住、不参与轮转。 |
| `RESCUE_MAX_ATTEMPTS` | `4` | 启动重试上限。默认 = `RESCUE_KEEP + 1`。 |
| `RESCUE_EVIDENCE_KEEP` | `3` | `evidence/boot-*` 证据目录保留份数。默认跟随 `RESCUE_KEEP`。 |
| `RESCUE_PROFILE` | `web` | 回退目标 profile（web = Web 界面；可选 cli 等）。 |
| `RESCUE_SELFHEAL` | `on` | 自愈总开关。与 `RESCUE_AUTO` 取与：任一为 off 则只诊断不自动改。 |
| `RESCUE_REMOVE_LIMIT` | `2` | 单容器生命周期内"自动摘插件"次数上限。 |
| `RESCUE_ROLLBACK_LIMIT` | `2` | 单容器生命周期内"回快照"次数上限。 |
| `RESCUE_DIAGNOSE_EVIDENCE` | `on` | 是否把每轮 dsh 启动输出 tee 捕获到 `$DSH_HOME/.rescue/evidence/`。 |
| `RESCUE_EVIDENCE_MAX` | `20971520` | 单个 `dsh.log` 轮转上限（字节）。 |
| `RESCUE_INCIDENT_KEEP` | `20` | `$DSH_HOME/.rescue/incidents` 保留份数。 |
| `RESCUE_SNAPSHOT_ON_HEALTHY` | `on` | 健康后是否自动拍"已证明能启动"的基线快照。占用 `RESCUE_KEEP` 份数，最新一份钉住不轮转。 |
| `RESCUE_SNAPSHOT_MODE` | `hardlink` | `hardlink` = `cp -al`（秒级、几乎不占空间，但与 live 共享 inode，**就地改写会同时污染历史快照** —— 用 `rescue verify` 检测）；`copy` = `cp -a`（真正不可变，代价是 `node_modules` 全量复制）。 |
| `RESCUE_SELFHEAL_WINDOW` | `86400` | 自愈预算的滑动窗口（秒）。窗口内累计的"自动摘/回快照"次数达到上限后转 report-only；窗口过期自动清零。 |
| `RESCUE_AUTO_LIFEBOAT` | `on` | 自愈彻底失败（预算耗尽仍起不来）后，是否自动降级进救生舱。 |
| `TMPDIR` | `/data/dsh/tmp` | 临时文件根目录。**默认指到数据卷**，而不是 tmpfs `/tmp`（后者硬上限 128m，dsh 做临时任务/验证测试时容易被写满）。dsh 的工具输出溢出 / 命令输出 spool / 工作区变更捕获都走 `os.tmpdir()`，会随之迁移。回收用 `rescue clean`。 |
| `RESCUE_TMP_KEEP_MIN` | `1440` | `rescue clean` 回收 `TMPDIR` 下 dsh 临时产物时的保留窗口（分钟）。阈值内视为"可能仍在使用"，绝不删。 |

详见 [06 · 救援模式](06-救援模式.md)。日常排查期间建议 `RESCUE_AUTO=off`、`RESCUE_SELFHEAL=off`，只诊断不自动改。

## 2. 资源限制 / 运行时

| 变量 | 默认 | 含义 |
|---|---|---|
| `NODE_MAX_OLD_SPACE` | `1024` | Node 堆上限（MB）。DSH 是多进程体系，实际 RSS 显著超过堆值（主进程+子进程+客户端 bundle），**堆值必须远小于 `MEM_LIMIT`**（建议 `NODE_MAX_OLD_SPACE * 1.5` 估算的 RSS 仍低于 `MEM_LIMIT` 的一半），否则 dsh 会被容器 OOM-kill（表现：对话/请求静默中断、FATAL ERROR）。 |
| `PIDS_LIMIT` | `512` | 容器进程数上限。`socat` fork 模式下每连接一个进程，无上限时并发连接可拖垮容器。 |
| `SOCAT_MAX_CHILDREN` | `64` | socat 并发连接上限。无上限时外部并发连接可耗尽容器内存。 |
| `MEM_LIMIT` | `2g` | 容器内存上限。N100 + 8GB 示例给宿主机系统留余量。 |
| `CPU_LIMIT` | `2` | 容器 CPU 限额。 |
| `TZ` | `Asia/Shanghai` | 时区。容器内所有日志与计划任务时区。 |

## 2.5 安全加固（非 root 运行 / capability / 只读）

自 v0.4.6 起，镜像默认以**非 root 用户**运行，并对容器做 capability 与只读根 FS 的收敛：

- **运行用户**：容器内 `node` 用户（镜像自带，uid=1000 gid=1000）。入口脚本先以 root 完成首启
  （把镜像 seed 复制进 `/opt/dsh`、把三个挂载卷 `chown` 给运行用户），再用 `setpriv`
  降权到 1000 后运行 dsh / socat / 升级 / rescue。容器内常驻进程**不是 root**。
- **`USER_UID` / `USER_GID`**：覆盖非 root 运行用户的 uid/gid。**通常无需设置** ——
  不设即 `1000:1000`（compose 的 `${USER_UID:-1000}` 与 entrypoint 双层兜底），而镜像自带的
  `node` 用户本身就是 `1000`，与多数 NAS/宿主的首个非 root 用户及三个挂载卷属主天然契合。
  仅当宿主上这三个卷的属主**不是 1000**、且你希望以那个 uid 运行时才覆盖。
  ⚠ 该 uid 最好能在容器 `/etc/passwd` 中查到（`1000` = 自带的 `node` 用户）：`setpriv --init-groups`
  需要能反查到用户名；填一个查不到的 uid **不会导致启动失败**，但 entrypoint 会退化为
  **"不带附加组"降权**（uid/gid 仍按你指定的生效，只是 supplementary groups 为空）。
  （旧文档说"须与 Dockerfile 构建参数一致"是错的：镜像已不再声明该 build-arg，它曾是死参数。）
- **capability 收敛**（`docker-compose.yml`）：`cap_drop: [ALL]` + 最小白名单
  `cap_add: [CHOWN, DAC_OVERRIDE, SETUID, SETGID]`。这四个能力仅供首启 chown 挂载卷
  与 `setpriv` 降权；运行期 dsh/agent 进程（uid 1000）不具备它们。
- **只读根 FS**：`read_only: true` + `tmpfs /tmp`（128m）。根 FS 只读后系统目录不可写，
  需要落盘的只有卷与 /tmp。**dsh 自身的临时文件不走 /tmp**：`TMPDIR` 默认指到数据卷
  `/data/dsh/tmp`（见 §1 的 `TMPDIR`）—— /tmp 是内存硬上限 128m，dsh 做临时任务/验证测试时
  很容易被写满，迁移后 /tmp 只剩少量系统级临时文件。`NPM_CONFIG_CACHE` 默认指向
  `/opt/dsh/.npm-cache`（可写卷内，
  由入口脚本首启创建并 `chown` 给运行用户；root 的 `docker exec npm` 与 node 用户均可用），
  确保 `npm install -g` 升级与救援清理仍可用。
- **启动时关闭 profile 的 HMR**（`--patch` 叠加层）：HMR 依赖的 native addon
  （`node-addon-require-builtin`）在只读根 FS 下可能没有可用 binding，此时 dsh 会抛
  `--expose-internals is required for HMR service` 并崩溃；而容器里改配置本就该走
  `docker restart` 生效。故入口脚本在**每条启动命令**上注入
  `--patch /opt/dsh-rescue/hmr-off.yml`（叠加层见 `scripts/hmr-off.yml`），关闭 base 组合包的
  `hmr` 条目。
  **2026-09-18 机制换代**：DSH 0.1.6-alpha.2 删除了 profile manifest 的 `patchReload` 字段
  （此后它被**静默忽略**），HMR 改由 `hmr` 条目按「是否由启动器拉起」自动启用；于是早先
  「首启把 `patchReload` 改写成 `startup`」的做法在 alpha.2 上**已失效**（HMR 实际会开着）。
  改用启动参数后，关闭动作不再依赖某个版本的 manifest 字段，容器内升级/回退 dsh 都不会让它失效。
  若你确实需要生产环境的 live 热重载，请自行关闭 `read_only` 并去掉该叠加层。
- **NAS/内核注意**：`cap_drop:[ALL]` 在部分 NAS 存储后端（NFS / 部分存储池）下可能影响
  卷内权限与硬链接（rescue 快照 hardlink 用 `cp -al`）。已在本仓库 e2e 沙箱验证通过；
  部署到目标平台前建议先跑 `scripts/t/e2e-container-selftest.sh` 确认卷权限与 rescue 链路。
- 这些加固不可关（属默认安全姿态）；如需更宽松的行为请自行编辑 `docker-compose.yml`。

## 3. 构建与镜像

| 变量 | 默认 | 含义 |
|---|---|---|
| `DSH_IMAGE` | `ghcr.io/steven-stack-s/dsh-docker-server:latest` | 启动时 `pull` 的镜像。要彻底锁版本请显式指定 `v<项目版本>-dsh-<dsh版本>` 格式 tag。 |
| `DSH_VERSION` | （未进 compose） | **仅用于手动 `docker build`**：`--build-arg DSH_VERSION=<版本>`，固定写入 seed 的 dsh 版本。compose **刻意不提供本地构建路径**——`image:` 与 `build:` 同名时，只要本地没有该镜像，`docker compose up -d` 会回退成"用当前目录构建"而不是报错，于是在「换了 tag 但该 tag 还没发布」时会**静默跑一份用旧代码构建的镜像**（真机 2026-09-17 踩过）。详见 `docker-compose.yml` 顶部注释。 |
| `PNPM_VERSION` | （未进 compose） | 同上，仅用于手动 `docker build`，固定写入 seed 的 pnpm 版本。 |
| `REMOTE_PLUGIN_VERSION` | （未进 compose） | 同上，仅用于手动 `docker build`：镜像内置的默认认证插件（`@xgone/dsh-remote`）版本。**置空**（`--build-arg REMOTE_PLUGIN_VERSION=`）可构建不带该插件的镜像，首启自动回到无认证的内网直连模式。 |
| `REMOTE_PLUGIN_NAME` | （未进 compose） | 同上，仅用于手动 `docker build`：默认认证插件的包名（默认 `@xgone/dsh-remote`），便于换用 fork 或私有源。 |
| `DSH_REMOTE_SEED` | `/opt/dsh-remote-seed` | 镜像内插件离线副本的位置。entrypoint 首启从这里复制插件进 profile，**不需要联网**。正常无需修改；仅当你自建镜像改了该路径时才需同步。 |

## 3.5 默认认证插件（@xgone/dsh-remote）

自 v0.6.0 起，镜像**默认安装并启用**认证插件，首启自动创建一个管理员账号：

| 变量 | 默认 | 含义 |
|---|---|---|
| `DSH_SETUP_REMOTE` | `on` | 总闸。`off` = 完全不装插件、不建账号，回到历史行为（无认证层、仅内网直连）。此时用局域网 IP 访问需自行配置 `DSH_TRUSTED_HOSTS`，否则 `/api` 会 403。 |
| `DSH_DEFAULT_ADMIN_USER` | `admin` | 首个管理员的用户名。**仅当账号库为空时使用** —— `$DSH_HOME/auth/store.json` 已有账号时本项被忽略（不会改名、不会重置密码）。 |
| `DSH_ADMIN_PASSWORD` | （空） | 首个管理员的密码。**留空 = 随机生成 16 位**并打印到首次启动日志（推荐）。填了则不打日志（适合用密码管理器管理的场景），且需 ≥6 位。 |

**取密码**（仅在真正创建账号的那一次打印）：

```bash
docker logs dsh 2>&1 | grep -A9 'first-boot admin credentials'
```

> 📌 **日志翻不到了也不要紧**：密码同时被明文写进
> `$DSH_HOME/profiles/web/cordis.patch.yml`（权限 0600），随时可取回，**不必重置账号**：
>
> ```bash
> docker exec dsh grep -A8 'id: remote' /data/dsh/profiles/web/cordis.patch.yml
> ```
>
> 首启日志的横幅里也印了这个路径（`stored   : ...`）。

**行为细节**（都很容易被误解，故逐条写明）：

1. **密码只打印一次**。判据是账号库是否存在账号，而不是"容器启动了几次"：账号一旦建立，
   之后无论重启还是重建容器都不再打印 —— 否则密码会被写进每一次 `docker logs`，
   而日志常被转发、归档或贴进 issue。忘记密码时删除 `$DSH_HOME/auth/store.json`
   （即 `<DSH_DATA_DIR>/auth/store.json`）后重启容器即可重新生成；**这会删掉所有账号与 MFA 配置**。
2. **不覆盖已有账号**。插件在账号库非空时会忽略配置里的 `bootstrap` 段并打一行 warn，
   因此用户自行改过的密码不会被镜像重置。
3. **明文会落盘**：`$DSH_HOME/profiles/web/cordis.patch.yml` 里的 `bootstrap.password` 是明文
   （文件权限 0600，仅属主可读）。这既是插件的既有用法，也是"无浏览器也能预置凭据"的唯一途径。
   首次登录后建议改密码并开启 MFA；改密后该段即失效（账号已存在，bootstrap 不再被读取）。
4. **离线可用**：插件副本在镜像内（`DSH_REMOTE_SEED`），首启复制进 profile，不需要联网。
   这与 DSH 本体的 seed 机制同款，保证内网/NAS 部署也能开箱即有认证。
5. **不会被镜像顶回旧版**：profile 里已有该插件时 entrypoint **不覆盖** —— 你用
   `dsh plugin add @xgone/dsh-remote@<更高版本>` 升过的版本会被保留（升级插件走 `dsh plugin`，
   镜像种子只负责"从无到有"）。

## 4. 工具链

| 变量 | 默认 | 含义 |
|---|---|---|
| `NPM_REGISTRY` | `https://registry.npmmirror.com` | 容器内 npm / pnpm 使用的镜像源。首次安装/升级 DSH、装 pnpm 时走这里。国内可保留默认；海外部署建议改为官方源 `https://registry.npmjs.org`。 |
| `NPM_CONFIG_CACHE` | `/opt/dsh/.npm-cache` | 容器内 npm / pnpm 的下载缓存目录。默认指到挂载卷内可写目录（只读根 FS 下 `/root/.npm` 不可写，会让升级链路失败）；可覆盖，但必须指向可写目录。清理功能（`rescue clean`）会清空该目录下的 `_cacache`。 |

## 6. 调试小贴士

- **查看 compose 实际生效的环境变量**：`docker compose config` 输出最终解析后的 YAML，里面能直接看到每个变量的最终值。
- **对比 .env 与默认值差异**：`docker compose config | grep -E '^\s*- [A-Z_]+=' | sort` 列出所有进入容器的环境变量，逐项对比默认值。
- **临时覆盖而不污染 `.env`**：`VAR=value docker compose up -d`（docker compose 允许通过命令行 env 覆盖）。
